1. RESUMEN DEL PROYECTO
================================================================================

El Sistema ISA es una plataforma para digitalizar el proceso de evaluación de
desempeño discrecional de ISA Corporativo.

OBJETIVO:
- Reemplazar el flujo físico (Excel + papel) por una plataforma digital
- Automatizar el flujo de autorizaciones y firmas electrónicas
- Garantizar trazabilidad y auditoría completa
- Calcular bonos basados en desempeño y EBITDA

ALCANCE:
- Captura digital de evaluaciones
- Máquina de estados para workflow de aprobación
- Firma electrónica simple (Base64 Canvas)
- Cálculo automático de bonos
- Notificaciones automáticas
- Auditoría de todos los cambios

USUARIOS:
- Coordinadores (evaluados)
- Gerentes (evaluadores/aprobadores)
- Directores (aprobadores finales)
- Contraloría (solo lectura)

3. ARQUITECTURA: DEFENSE IN DEPTH
================================================================================

Esta arquitectura separa estrictamente las responsabilidades en capas concéntricas,
garantizando que ninguna vulnerabilidad en una capa comprometa las demás.

┌─────────────────────────────────────────────────────────────────────────────┐
│                        views.py (APIS)                                     │
│  - Capa de TRANSPORTE                                                      │
│  - Recibe peticiones HTTP                                                   │
│  - Valida JWT authentication                                               │
│  - Valida permisos RBAC                                                     │
│  - Valida esquemas (DRF Serializers)                                        │
│  - Delega a services                                                       │
│  - PROHIBIDO: Lógica de negocio, ORM queries                               │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                        services.py                                          │
│  - Capa de NEGOCIO                                                         │
│  - Lógica de estado (State Machine)                                        │
│  - Cálculo de bonos                                                        │
│  - Validaciones complejas                                                  │
│  - Envía eventos al audit_service (HTTP)                                   │
│  - PROHIBIDO: Queries directas a BD                                        │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                        selectors.py                                         │
│  - Capa de LECTURA                                                         │
│  - Consultas optimizadas (select_related, prefetch_related)                │
│  - NO modifica datos                                                       │
│  - Centraliza queries complejas                                             │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                        models.py                                            │
│  - Capa de DATOS                                                           │
│  - Define estructuras de tablas                                             │
│  - managed = False (NO crea/modifica tablas)                               │
│  - Constraints y validaciones de BD                                        │
└─────────────────────────────────────────────────────────────────────────────┘

REGLA CRUCIAL: views.py → services.py → selectors.py → models.py
                (nunca en sentido contrario)

  web:
    build: ./backend_django
    command: >
      sh -c "chmod +x entrypoint.sh && ./entrypoint.sh"
    volumes:
      - ./backend_django:/app
    ports:
      - "8000:8000"
    env_file:
      - .env
    restart: unless-stopped

ENTRYPOINT.SH:
───────────────
#!/bin/bash
set -e

# Esperar a Supabase
echo "Esperando conexión a Supabase..."
until PGPASSWORD=$DB_PASSWORD psql -h "$DB_HOST" -p "$DB_PORT" -U "$DB_USER" -d "$DB_NAME" -c '\q' 2>/dev/null; do
  echo "Supabase no disponible, reintentando en 5 segundos..."
  sleep 5
done

echo "Supabase disponible. Ejecutando inspectdb..."

# Generar modelos desde Supabase
python manage.py inspectdb > apps/models_auto.py

# Migrar tablas internas de Django
python manage.py migrate

# Crear superuser si no existe
python manage.py shell < scripts/create_superuser.py

echo "Iniciando Gunicorn..."
exec gunicorn config.wsgi:application --bind 0.0.0.0:8000 --workers 4

11. MÁQUINA DE ESTADOS (FSM)
================================================================================

DIAGRAMA DE ESTADOS:
────────────────────

       ┌──────────────────────────────────────────────────────────┐
       │                                                          │
       │    ┌───────┐                                           │
       │    │ DRAFT │ ← Estado inicial                          │
       │    └───┬───┘   El evaluado puede editar                │
       │        │                                               │
       │        │ submit_evaluation()                           │
       │        ▼                                               │
       │    ┌───────────┐                                       │
       │    │ SUBMITTED │ Ya no es editable por evaluado        │
       │    └─────┬─────┘                                       │
       │          │                                             │
       │          │ approve_by_coordinator()                    │
       │          ▼                                             │
       │    ┌────────────────────┐                              │
       │    │ PENDING_APPROVAL  │ ← En espera de firmas        │
       │    └─────────┬──────────┘                              │
       │              │                                         │
       │     ┌────────┴────────┐                                │
       │     │                 │                                │
       │     ▼                 ▼                                │
       │  ┌─────────┐   ┌───────────┐                         │
       │  │ APPROVED│   │ REJECTED  │ ← Requiere comentario    │
       │  └────┬────┘   └─────┬─────┘                         │
       │       │              │                                 │
       │       │              │ (comentario obligatorio)        │
       │       │              │                                 │
       │       │              └─────────────────────────────────┤
       │       │                                                  │
       │       ▼                                                  │
       │  ┌─────────┐                                            │
       │  │ CLOSED  │ ← Estado final, inmutable                  │
       │  └─────────┘                                            │
       │                                                          │
       └──────────────────────────────────────────────────────────┘

REGLAS DE TRANSICIÓN:
─────────────────────

| Estado Actual        | Acción                  | Estado Siguiente      | Condiciones                    |
|---------------------|-------------------------|----------------------|--------------------------------|
| DRAFT              | submit                  | SUBMITTED            | Todas las competencias llenas    |
| SUBMITTED          | approve                 | PENDING_APPROVAL     | Evaluador es Coordinador       |
| PENDING_APPROVAL   | approve                 | APPROVED             | Si no requiere gerente          |
| PENDING_APPROVAL   | escalate                | PENDING_APPROVAL     | Si requiere gerente, aprobar    |
| PENDING_APPROVAL   | reject                  | DRAFT                | Comentario OBLIGATORIO         |
| APPROVED           | close                   | CLOSED               | Solo Director                  |

VALIDACIONES:
─────────────
- No se pueden saltar estados
- Solo el evaluador puede editar en estado DRAFT
- Solo el aprobador puede aprobar/rechazar en PENDING_APPROVAL
- REJECTED requiere comentario obligatorio
- CLOSED es inmutable

JERARQUÍA:
──────────
- Campo manager_id en usuarios permite jerarquía recursiva
- El sistema consulta automáticamente al manager del aprobador
- Ejemplo: Coordinador → Gerente → Director

CÁLCULO DE BONOS:
─────────────────
Fórmula:
  monto_final_bono = salario_base × (impacto_ebitda / 100) × performance_index × factor_rol

Donde:
- salario_base: Capturado al momento de aprobación (snapshot)
- impacto_ebitda: Porcentaje de alcance de meta (0.00-100.00)
- performance_index: Calificación global (1.00-5.00)
- factor_rol: Depende del nivel (Coordinador: 1.0, Gerente: 1.2, Director: 1.5)

FIRMAS DIGITALES:
─────────────────
- Capturadas via Canvas HTML5 en frontend
- Almacenadas como texto Base64
- Validadas: debe ser data:image/png;base64,... o similar
- IP del firmante capturada automáticamente
- Timestamp del servidor (no del cliente)

AUDITORÍA:
──────────
- Cada cambio de estado registra en historial_estados
- Cada firma registra en aprobaciones
- Cada acción de sistema registra en logs_sistema
- Envío asíncrono a audit_service (FastAPI) si disponible

NOTIFICACIONES:
───────────────
- Recordatorios cada 3 días si hay evaluaciones pendientes
- Notificación al gerente cuando subordinado envía evaluación
- Notificación al evaluado cuando evaluación es aprobada/rechazada
